# 模型勝率追蹤 V1.2

日期：2026-10-21。沿用 ModelTracker、SQLite WAL、現有 Google Sheet 與有界背景同步；不新增行情訂閱／查詢、不改進停目、保利門檻及交易成本公式。

## 來源與原因

- 股期轉接明確保存「股期戰略室」及股票／期貨、當沖／波段類型；指數與選擇權保留原來源及類型。
- 舊紀錄僅在商品、契約腿與既有類型可以證實來源時補標；不能確認者標「未確認」。交易 ID、既有成交、成本、損益與事件內容不重算。
- 篩選依日期、來源、原始版本識別、商品、其他條件逐層縮小；下層不適用值在建立 widget 前清除。版本標籤僅顯示，不取代原始版本鍵。
- 最後等待原因、失效原因／時間、未進場分類與缺口原因分開保存。等待原因改變才新增事件；模擬進場不再刪除先前原因。

## 二次進場及執行鏈

- 僅 V1.2 新計畫支援；V1.0／V1.1 的交易 ID 與歷史保持原制。
- 原始計畫 ID 包含來源、類型、市場、實際商品／月份、模式、策略版本、方向、到期及排序後的選擇權腿。當沖包含交易日；波段沿用原有效期與休市規則。
- 計畫價格沿用第一次發布的凍結價位，不因每輪刷新新建相同計畫。每次執行 ID 由「計畫 ID＋前一執行 ID」決定，首次使用空前綴；次數是可驗證的執行鏈序位，不能決定身分。
- 只在前筆有完整證據且已平倉後追蹤重入。原進場條件須以新鮮行情先解除，再重新成立；若策略真的提供新的許可識別，可採該新許可。檢查時間或每次 rerun 不是新許可。
- 新進場必須晚於前筆出場；不能重用舊成交。持續停在觸價區不重複建倉；中斷、缺序、過期、休市及行情不足取消未完成的重入解除狀態。
- 每次重新凍結當下成本與指標、重新計算滑價、費稅、風險及保利；不沿用上筆保價、權利金或已結案欄位。
- 選擇權各腿重新驗證實際成交、時間差、價差範圍與到期；單腿及價差均不得使用理論價代替。
- 本機先保存候選與證據，不等待網路。Apps Script 在原 ScriptLock 內驗證 ID、前筆、序位、解除／新許可時間及各腿證據；缺少父筆保持待同步。跨月波段可依父筆月份核對。
- 共用儲存回讀確認前，V1.2 候選不納入正式績效。不同裝置提供矛盾成交或成本時保留衝突並排除績效，不挑選獲利較高的結果。

## 缺口及事件

- 本機序號是每個實際商品、每個串流 epoch 的觀測順序，不是跨商品／跨裝置共用的交易所序號。
- 修正同時間舊成交重播使序號倒退的問題：同一串流已處理過的序號不再推進狀態；不同串流不可因時間及序號相同就跳過重連檢查。
- 真正缺序保留缺漏起迄序號、串流及時間。修正誤判不代表可以移除已保存的舊缺口；無法證明先後的交易仍排除正式績效。
- V1.2 連續且相同原因的診斷事件可保存為起訖時間／次數區間。進場、出場及保利事件不合併；不同缺漏證據不混在同一區間。
- 舊原始事件完整保留，不以截斷、刪除或只留最後幾筆減量。本次資料轉換前，正式月份 JSON、本機 SQLite 與 Apps Script 已保存獨立備份及 SHA-256 manifest。
- 舊版大量事件移至同一試算表的 `strategy_events:YYYYMM` 分區，以原始 JSON 字串及 SHA-256 校驗。主紀錄保留完整關鍵事件及最後的各類診斷、原始事件數與封存關聯；不修改成交、損益或缺口旗標。
- 封存採鎖內先寫原始事件、回讀校驗，再原子提交主紀錄。分段寫入失敗時原主紀錄不變；可安全重試。舊裝置未升級格式的寫入會明確拒絕，本機待同步事件須先核對封存，再連同尚未上傳的新事件合併。

## 統計、分層與匯出

- 交易績效：每筆有效已平倉執行各算一次；勝率、平均 R、累積淨損益、最大回撤與保利出場比例分別顯示。平手納入交易數，不計獲勝。
- 原始計畫績效：相同計畫歸組，分開顯示觸發率、有效率、首次與後續進場勝率、累積損益與未進場原因。父筆尚未載入時不把部分紀錄冒充完整計畫。
- R 沿用已保存的 `結果(R)`；選擇權目前是標的觸發 R，與金額保利 R 分開說明，不回算舊交易。
- 最近 90 天涵蓋的月份為自動載入範圍（邊界月份仍完整保存）；仍活動、待同步及明確查詢的舊月份例外保留。既有日期預設「今天」不變；舊月份完整保存，按需讀取，不另建第二份 Sheet。
- 行情消費者只讀取收到報價的商品範圍，不在每輪解析所有未結案歷史。模型頁的統計與表格讀取不攜帶完整事件；事件明細只讀本頁、最多 500 列。
- Excel 點擊後才讀取完整篩選交易；封存未載入時先按「準備完整 Excel」，沿用同步工作背景讀取並驗證，完成前停用匯出。歷史明細只列事件數，完整事件獨立工作表按交易 ID 關聯。逐列寫入，超長文字可逆分段，公式樣式的資料一律以文字保存。

## 本機效能比較

使用 `python tests/model_v12_benchmark.py f63eea5 0` 與相同指令尾數 `1000`；完整載入舊／新模組、獨立 SQLite，6 股票＋5 期貨，每商品 4096 筆串流緩衝、50 筆新成交，四輪計時。記憶體另輪量測，避免追蹤器干擾計時。

| 無關歷史活動紀錄 | 舊版／新版每輪中位數 | 舊版／新版每輪 CPU | Python 暫存峰值 |
|---|---|---|---|
| 0 筆 | 93.31／99.27 ms | 89.84／101.56 ms | 0.06／0.07 MiB |
| 1000 筆（每筆 50 事件） | 172.75／100.81 ms | 175.78／93.75 ms | 14.41／0.07 MiB |

## 發布與驗收

### 2026-10-22 成交證據銜接修正

- 等待進場的最新價格與來源時間同步保存，跨裝置接手時能以同一筆時間／價格驗證重疊成交。價格不同、重新連線及真正序號缺漏仍保留缺口。
- 佇列仍有已接收證據時，先按原順序消化，再判斷監控停止；每筆行情原有的時效、序號及斷線驗證照常執行。佇列清空後若監控確實停止，仍記錄中斷。
- 不修改進場品質、停損停利、有效績效公式或歷史缺口，不補造正式成交。回歸涵蓋可驗證接手後獲利／虧損、錯價拒絕、積壓後出場及真正離線。

1. 核對正式備份 manifest，保留舊版本及回滾路徑。
2. Apps Script 新部署須先提供 `model_reentry:1`、`model_history:1`、`model_events:1`；Python 仍支援舊資料。未提供能力時新執行留本機待同步，不假裝已同步。重啟新版 App 後才對指定月份送出 `archive_model_events`；不在一般刷新中執行封存。封存後應先讀完整事件還原格式，再回退舊 Python，不能直接回退不識別封存的程式。
3. 覆蓋股票／期貨當沖波段、指數兩種計畫、BC／BP／價差、停利／停損／保利、持續觸價、缺口／重連／過期、跨裝置及跨月。
4. 比較更新耗時、CPU、記憶體與大量歷史查詢；確認不新增 Shioaji API 或訂閱。
5. 完整 CI、實際 Apps Script JavaScript、Streamlit AppTest 通過後才合併。部署後確認來源篩選、正式回讀與舊紀錄完整性；合成測試不能冒充真實新交易及手機雙裝置驗收。
