# 策略勝率自動追蹤 V1.0

## 使用與資料口徑

交易損益室預設開啟「模型勝率追蹤」，位於當沖損益室左邊。開啟股期主表或獨立分析的既有自動更新後，僅追蹤該表實際商品；停用、登出或離開監控範圍會標記缺口。不建立額外行情查詢、訂閱、下單或全天候服務，選股、排序、排名、策略公式不改動。股票的「即時更新最新成交價」仍不更新模型紀錄。

有效訊號使用既有方向、風控、進場信心與策略計畫門檻。版本為策略函式及風控設定的摘要；舊紀錄凍結當時的價格、指標、條件、版本與成本。交易 ID 由交易日、商品、策略、版本、方向及進場／停損／目標價建立，不使用裝置收到訊號的時間。

等待進場 → 模擬持倉 → 已平倉；另外保存訊號失效、資料不足、監控中斷。進出場依實際收到、含原來源時間與順序的成交推播，不回填計畫價成交。第一筆證據已超過目標時訊號失效；同筆進場證據不兼作出場。滑價一律向不利方向計入。只以具有有效金額、完整行情的已平倉交易計算勝率，平手列入交易數但不計獲勝。

同一根 K 同時觸碰停利／停損、佇列溢位、行情失效、停用監控、服務重啟或連線中斷，均保留未確認標記。已有另一個裝置完整確認的結案可以恢復正式結果；模擬成交價或成本衝突則排除績效。來源切換需有與上次觀察相符的重疊成交證據。波段在正常休市期間不自動判定缺口，但重啟／重新訂閱／不連續序號仍算缺口。當沖沒有收盤成交證據，不估算收盤或隔日損益。

### 成本

預設股票 1,000 股、手續費 2.8 折、單邊最低 20 元；期貨 1 口、單邊每口手續費 50 元；每次成交滑價 1 跳。可在模型頁調整，僅套用新訊號。手續費為模擬設定，並非券商實際帳單。股票稅費沿用交易損益室當沖／波段口徑；股價依現有跳動單位。股價類期貨稅率 0.00002，未知稅率或乘數商品不納入有效績效。

指數期貨每點價值：TX 200、MTX 50、TMF 10、TE 4,000、TF 1,000 元；不能沿用主表指數欄顯示用的乘數 1。股票／ETF 期貨沿用既有已確認契約乘數。

參考：[期交所稅費](https://www.taifex.com.tw/cht/4/feeSchedules)、[電子期貨契約](https://www.taifex.com.tw/cht/2/tE)、[金融期貨契約](https://www.taifex.com.tw/cht/2/tF)。

### 績效與匯出

提供有效交易數、勝率、獲勝／虧損、平均獲利／虧損、累積損益、獲利因子、期望值與最大回撤；按市場／模式／版本、方向／環境、指標及條件分組。訊號有效率＝有效已平倉／全部訊號；資料完整率＝無缺口訊號／全部訊號。無虧損樣本時獲利因子留空，避免以任意數字表示。指標分組是「進場時具該指標證據的交易」，不表示因果或單一指標的獨立勝率。

日期、商品、模式、方向與版本可篩選。明細每頁 100 筆，點擊 Excel 才建立檔案，輸出全部篩選紀錄及事件，數字保留數值類型。舊版手動紀錄沿用原檔案與 scope，不併入新版統計；2026/10/10 起移除模型頁的舊版顯示入口。

## 同步與部署

本機使用 SQLite WAL、交易 ID 主鍵及待同步旗標；每個程式共用一個有界背景寫入佇列。行情 callback 只保存有界成交證據，不做檔案或 HTTP 操作。資料異動後每 30 秒批次合併、POST、GET 回讀驗證；失敗保留待同步。模型頁顯示同步時間／錯誤原因，不把待同步說成已同步。

Google Sheets 使用原 `strategy_signals` 為月份索引，`strategy_signals:YYYYMM` 分月保存模型交易。Apps Script ScriptLock 保護讀取、合併、寫入和索引更新；依 ID／事件 ID 合併，完整已平倉不被舊等待／持倉覆蓋。採完整分段提交版本，部分寫入失敗時仍讀取最後完整版本。月份版本由伺服器產生並單調遞增，不能用裝置時間決定是否有更新。原手動紀錄與刪除標記獨立合併保留。

必要部署：將本專案 `google_apps_script.gs` 完整替換至目前綁定 Google Sheet 的 Apps Script，更新現有網頁應用程式部署的版本，保留目前執行身分／存取設定／URL。現有 `app_cache` 不需清除或搬移。應先確認 GET `scope=strategy_signals` 回傳 `model_schema:1`；缺少時程式禁止正式模型寫入，保留本機待同步，避免新版資料被舊後端覆寫。

之後須做正式 POST/GET 回讀及兩裝置相同／不同商品驗收；不可僅憑單元測試宣稱跨裝置成功。服務容器重建可能移除尚未同步的本機檔案，正式 Google Sheet 尚未部署或不可用時，不能保證跨容器還原。

## 驗證與效能界線（2026-10-08）

新增 22 項行為測試：停利、停損、未進場、同 K 歧義、資料失效、佇列缺口、重複 ID、跨裝置合併、不同商品、讀寫失敗重試、稍後登入、重啟、中斷恢復、原計畫凍結、增量統計與更正、收盤證據、實際股票／期貨策略入口、完整頁面 AppTest、真正 Excel 數值與防公式注入。Apps Script 測試執行實際 JavaScript doGet/doPost，使用 Sheet／Lock 測試替身，涵蓋部分分段寫入失敗與回復。

本機六檔股票，200 次測量（包含 tracemalloc）：原 DataFrame 複製中位 0.154 ms，加入實際策略紀錄入口及非阻塞送入佇列後 11.04 ms，新增約 10.89 ms。200 次 CPU 時間分別 0.031／2.313 秒；該階段 Python 配置記憶體峰值約 205 KiB；六檔股票＋五檔期貨、各 4,096 筆成交證據滿載約 13.72 MiB。六檔首次背景寫入約 13.47 ms；已有 10,000 筆已結案歷史時，處理同六檔約 11.82 ms；萬筆載入 380.48 ms，首次完整統計 365.09 ms。新結案之後只累加績效；相同資料使用快取，主表每輪不掃描完整已結案歷史。同步只讀變更月份；Apps Script 先讀輕量索引，再取所需 scope 的完整版本 JSON，原股票／公司同步不載入全部模型歷史。

以上是隔離的本機紀錄入口與儲存測量，基線僅 DataFrame 複製，**不是正式站完整每輪更新／CPU／RSS 的前後實測**。測試提供的 API 物件無行情查詢方法，證明紀錄入口沒有額外 snapshots/ticks/kbars；正式永豐帳戶流量尚未實測。

完整 pytest、Ruff 與 CI 結果以此改版 PR 為準。瀏覽器及電腦工具初始化仍失敗：`windows sandbox failed: helper_unknown_error: setup refresh had errors`／`trusted Node process exited unexpectedly`；真實電腦＋手機訊號同步、700px 以下正式畫面及雲端效能比較尚未驗收。不能把受控測試替代上述實測。


## 本次追加：同日月營收行事曆

舊事件只有 revenue.code，或事件 ID 只有公告日期時，同月份不同公司可能被合併或未被選取。快照讀取遷移公司代碼、合併依公司＋月份識別、勾選沿用該代碼，公告日校正欄位也不再使用空公司鍵。三項新增回歸測試涵蓋同日台積電／富喬、部分同步、同公司更新、勾選限制與完整桌機／手機日曆 HTML。未確認公告日不推估為今天。


## 2026-10-08 正式端點回讀驗證

使用使用者提供的既有 `/exec` 端點，已讀得 `model_schema:1`。兩個獨立 HTTP 客戶端同時向 `strategy_signals:202610` 寫入空交易批次，POST 與 GET 均成功，月份索引及版本也完成回讀；之後兩個獨立 SQLite 客戶端還原同一資料。沒有加入人工測試訊號或交易。目前正式模型與手動紀錄均為零，因此這次驗證證明傳輸、月分區及索引可用，**不等於非空真實交易的兩裝置驗收**。既有非空資料合併／去重／失敗重試仍以行為測試驗證。

實際空批次寫入加回讀分別花 25.46／24.19 秒；完整上述驗證為 89.4 秒。原模型 HTTP 使用固定 scope URL 與 8 秒逾時，在實測出現 404／ReadTimeout；模型 GET 改用專案既有 `_ts` 與 no-cache 標頭，GET／POST 採 5 秒連線、35 秒讀取逾時，以容納 Apps Script 最多 30 秒共享鎖等待。網路只在原背景寫入工作內執行，不阻塞主表；失敗仍保留 dirty 待同步旗標。新增回歸測試核對兩次 GET 不共用快取鍵及 POST 逾時後仍可重試。

只讀正式 `company_events`，確認台積電（2330）與富喬（1815）都已勾選，且保存了 2026/10/08 公布的 11509 月營收。將正式快照帶入實際正規化、勾選篩選與單日 HTML 函式，兩筆各顯示一次：台積電 9月 MoM-0.57%／YoY+54.65%；富喬 9月 MoM+2.87%／YoY+82.14%。這是正式資料＋目前程式函式的驗證，正式瀏覽器畫面尚未取得。
