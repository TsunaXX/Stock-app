# 股期戰略室維護參考

## 資料來源與口徑

- 週轉率排行維持「上市＋上櫃＋ETF、依當日正常交易成交股數 ÷ 最新發行股數／受益權單位數」的統一口徑。主要來源為 TWSE＋TPEx 官方資料，兩個市場資料日一致才可合併；不可直接混用兩個市場各自的現成排行。
- 官方週轉率按鈕同時完成抓取、日期驗證、產生相容 `Report.csv` 的資料與執行既有分析。快速查詢標的固定排在設定的原排行 N 檔之後，不可擠掉排行名額。
- Goodinfo 僅保留人工對照與 CSV 備援，不再由雲端伺服器爬取。禁止把開發者工具複製出的 `cf_clearance`、`CLIENT_KEY` 或其他 Cookie 寫入程式、設定檔或雲端。官方來源失敗不得覆蓋上次成功排行。
- 若 Streamlit 雲端 IP 仍被 Goodinfo 阻擋，正式備援流程是由使用者瀏覽器開啟同一排行頁、完成驗證並匯出 CSV，再於股票戰略室「本機」上傳後執行分析。上傳解析須支援 CP950／Big5／UTF-8、前置說明列與內嵌「代號／名稱」標題；瀏覽器基於隱私不會讓 Streamlit 自動讀取裝置的下載資料夾，因此不可宣稱下載後免上傳。
- Goodinfo 若依雲端出口 IP 阻擋，增加瀏覽器指紋偽裝或等待時間不視為可靠修正；不可在程式內硬編使用者的 Cloudflare Cookie。完整的使用者端自動匯出／回傳需要獨立瀏覽器擴充功能或已授權的遠端瀏覽器服務，Streamlit iframe／一般 JavaScript 受跨來源與本機檔案權限限制，不能直接代替。
- 2026 CPI／大非農已有完整且核對過的 BLS 官方排程；該年直接合併此排程與 TradingView 備援，不可先對容易封鎖雲端 IP 的 BLS 頁面做三輪重試。其他年份仍依序查 BLS ICS、年度總表與個別發布頁。這是首次載入的重要效能界線，不能用移除行事曆資料換速度。
- 盤前跨市場批次不可向 Yahoo 查 `TWF=F`（該代號在 Yahoo 不存在，會固定 404 並拖慢首次載入）；台指夜盤只使用已登入的 Shioaji 實際近月契約，未登入時顯示該來源未取得，不以錯誤商品代號冒充。
- 股票名稱與代號優先讀取 `stock_names.csv`；快速標籤統一保存為 `名稱(代號)`。
- 期貨成交量、結算行情與保證金以期交所 OpenAPI 為主。官方來源暫時失敗時顯示最後一次成功資料與日期，不得把未知保證金顯示為 0。
- 台股月營收數值以 MOPS 為主；公告日期優先採 FinMind 或可驗證的公司／公開報導來源，並保留人工校正。

## 價格與交易日規則

- 股票當日漲跌停價以該交易日之前一交易日收盤價計算。
- 14:30 前畫面與名稱底色判斷當日漲跌停；14:30 後若顯示隔日預估上下限，必須使用獨立欄位，不可覆蓋當日上下限。
- 當沖進場、停損、目標與支撐壓力點位都不得超出當日合法漲跌停範圍。
- 股票價格級距與漲跌停計算使用 `Decimal`，避免浮點誤差跨過合法 tick。
- 已公告但尚未開始的處置，以實際「下個開盤日處置」顯示；週末與連假必須跳至下一個交易日，不得以明天的日曆日期判定。
- 戰略備註的「漲停／跌停」只代表最新交易日 K 棒實際碰到以該日之前一交易日收盤價計算的限制價；盤後顯示的隔日預估限制價不可拿來產生標籤。
- 有夜盤的期貨在欄位顯示「日盤+夜盤」；行情 OHLC 與成交量必須屬於同一交易時段或正確的同一交易日，不可混拼。
- Shioaji 1.7 採契約延遲載入；期貨實際契約先用 `api.contracts.futures(root, delivery_month=...)` 查詢，再退回舊式 `api.Contracts.Futures`。期交所 `TX/MTX` 對應 Shioaji `TXF/MXF`。
- 月契約結算日以臺北時間 13:30 為切換點：切換前保留當月，切換後剔除當月、清除其即時排行／報價快取，並將次月重新標為近月。官方最後交易日優先於推算日；只有日期沒有時間時一律補 13:30。
- 「只顯示小型股票期貨」只保留商品類型為股票且標示小型的契約，不可混入 MTX、TMF 或 ETF 期貨。

## Google Sheet 持久化

- 股票快照、期貨戰略室快照、策略訊號、公司事件與費波快速標籤共用現有 Apps Script JSON 儲存，不另建使用者看得到的工作表結構。
- 上市／上櫃注意與處置的最後成功名單隨 `stock_strategy` 保存，手機重連或服務重啟時先顯示已查核快照；手動更新失敗不得用空名單覆蓋。
- 各資料區塊用自己的 `updated_at` 比較版本。股票較新不代表費波標籤或期貨快照也較新。
- 費波標籤只有五組有效值才可取代既有資料；保存時同時寫入 `fibo_tags_backup`。沒有更新時間的部署預設值不可覆寫雲端值。
- 費波一般啟動採裝置本機標籤優先，避免手機與電腦自動互蓋；使用者按「從 Google Sheet 重新載入」時必須只接受 `fibo_strategy`，雲端失敗不得退回本機後誤報成功。雲端保存必須 POST 成功後再 GET 回讀，五組標籤完全相同才顯示同步成功。
- Apps Script 的 scope 清單必須與程式一致，包含 `stock_strategy`、`fibo_strategy`、`company_events`、`strategy_signals`、`futures_strategy`；參考專案根目錄 `google_apps_script.gs`。
- 期貨本機快照使用 `futures_strategy_cache.json`，不得再把完整 universe 寫入 `config.json`。雲端只保留常用／更新中的契約並限制整體 payload；官方清單可重新抓取，不需保存全部遠月契約。
- 跨裝置保存採讀取、分區合併、寫入、必要時回讀驗證。遠端失敗時保留本機最後成功資料，不寫入空清單。

## UI 與效能

- Streamlit rerun 不應重做不可變歷史資料、啟動多個瀏覽器或重抓所有隱藏分頁；使用有界 TTL、last-known-good 與明確更新按鈕。
- 股票戰略室整段 UI／表格計算只在「股期戰略室 → 股票戰略室」實際開啟時執行；其他主分頁沿用 session/cache，不重建隱藏股票表。
- 主分頁與重型子分頁使用帶 `key`、`on_change="rerun"` 的狀態分頁；指數歷史、法人網頁、永豐 PDF 與行事曆網路來源只在對應分頁實際開啟時執行。切換分頁必須觸發 rerun，避免舊版延後載入後沒有真正抓資料的異常。
- 股票即時報價使用一次批次快照，不可逐檔呼叫；重抓日 K 策略指標不得同時重抓即時快照。公司同步固定最多三區並行、每批最多 12 家；注意／處置名單部分失敗時沿用最後完整成功資料。
- 內層股期／策略驗證與交易損益子分頁也必須使用有狀態分頁；期貨 universe、期交所保證金不得因隱藏子分頁而抓取。行事曆的獨立官方來源使用有界並行，但台股休市日必須先完成，依賴休市日調整的結算事件才可接續計算。
- 專案不使用 Streamlit 裸運算式 magic；`.streamlit/config.toml` 固定關閉 `runner.magicEnabled`，避免約兩萬行 `app.py` 每次冷編譯都進行整棵 AST 重寫。若日後新增依賴裸運算式顯示的程式，必須改成明確的 `st.write`／`st.dataframe`。
- 指數操盤室的 TWSE 加權日 K 必須逐月獨立快取並最多四個月份並行；當月以三分鐘 bucket 更新，單月失敗不可把既有完整歷史洗成空值。指數資料暫時失敗時沿用工作階段最後成功日 K並清楚標示。
- 行事曆 HTTP 不做頁面內多輪長等待；一次短截止失敗後由手動更新與逐來源 last-known-good 接手。當年度 CPI／大非農／ISM 已有核對完整排程時不得先抓 TradingView；GDP／核心 PCE 優先讀 BEA `/news/schedule/full`，官方當年度資料完整時不再額外下載備援。
- 行事曆依已儲存的追蹤選項啟動一個有界背景預載工作；開啟分頁時優先使用已完成結果，尚未完成時最多等待 12 秒並沿用最後成功資料。手動更新必須清除預載工作後重建。
- 股票／期貨主表及複數獨立計算依目前實際顯示列與所選「當沖／波段」模式呈現獨立排名；臺北時間 21:00 前使用前一個實際開盤日的完整盤後資料，21:00 起才切換為當日資料，週末與休市日回推最近開盤日。排名固定放在表格下方、策略信心明細上方，只排序排名清單，不可重排主表。股票綜合技術面、TWSE／TPEx 法人與融資券籌碼、估值基本面；期貨另納入期交所三大法人部位、成交量與未平倉，股票期貨可連結標的股票資料。當沖提高技術與籌碼權重，波段提高基本面權重；缺少不適用資料時重分配可用權重，不以零分懲罰。分數代表模式適配度並附多空方向與簡短原因，不沿用進場信心，也不宣稱為勝率。
- 排名總權重固定為：股票當沖「技術 55／籌碼 35／基本 10」、股票波段「40／30／30」、期貨當沖「50／45／5」、期貨波段「35／50／15」。股票技術包含 VWAP、均線、動能、ATR 與前高低價位結構；籌碼分拆外資、投信、自營商與融資券；基本面讀最新有效月營收、EPS、營益率及 PE／PB／殖利率。期貨優先使用價格×OI、法人淨 OI、基差、近遠月、量／OI 與標的現股資料；缺少 OI 增減、基差或期限結構時必須明示有效資料覆蓋率並在分類內重配，不可由目前 OI 絕對值假造變化訊號。期交所「股票期貨／ETF期貨」法人部位是全市場彙總，不可套到個別契約；個股與 ETF 期貨改用自身 OI、量／OI、基差、期限結構及標的現貨資料，只有可逐商品對應的指數期貨使用法人契約部位。不適用且官方未提供的指標不列入覆蓋率分母，真正抓取失敗的適用指標仍須反映缺口。
- 不可因效能優化而讓已開啟分頁缺資料。延後處理只適用目前確定未使用的重型視覺化或網路呼叫。
- 手機版優先確保表格可水平捲動、按鈕可點、欄位內容不截斷、圖表文字不重疊；桌機版維持緊湊。
- 台股表格顏色固定使用紅色表示上漲／偏多／漲停、綠色表示下跌／偏空／跌停；黃色表示等待或警示、藍色表示資訊／支撐壓力，避免同色同時代表相反含義。
- 選擇權的「模型估值差」是理論價減保守買進價，不可稱為期望損益。一般單買 BC/BP 只有在目標越過損益兩平、目標情境為正、報酬風險比至少 1.25，且模型機率、流動性與價差達標時才可標為建議；放寬層級仍須正目標損益與可達損益兩平，只能標為「小部位試單」，不可冒充一般門檻通過。

## 驗證

```powershell
python -m py_compile app.py
python -m pytest -q
```

涉及 Streamlit widget 或頁面流程時，再以 `streamlit.testing.v1.AppTest` 啟動全頁，確認沒有 `st.exception`。
